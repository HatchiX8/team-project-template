# LINE 售服系統架構初稿（討論稿）

> 說明可供討論的系統邊界、資料流與現有 monorepo 基礎；尚未形成正式技術選型或部署設計。

## 適用範圍

適用於 LINE 售服系統的系統組成討論。不定義資料庫結構、API Contract、基礎設施配置、資安審查結果或實際部署步驟。

## 概念架構

1. 外部客戶透過 LINE 官方帳號或網站入口進入 Web，完成身分辨識與公司關聯。
2. Web 呼叫 Server API，建立或查詢案件、取得與角色相符的資料。
3. Server 管理案件流程、權限、資料與附件，並對接 LINE 通知能力。
4. 內部處理人員與專案負責人透過 Web 受理、處理及追蹤案件。

此處是責任分界示意；登入協定、LINE 官方帳號串接、資料儲存和非同步工作方式都尚待設計。

## 現有 monorepo 基礎

| 區域 | 目前 repository 已建立的基礎 | 不應由此推定的事項 |
|---|---|---|
| `apps/web` | TypeScript + Next.js 前端專案 | 頁面架構、狀態管理套件已核准 |
| `apps/server` | TypeScript + Node.js + Express 後端專案 | 資料庫、ORM、認證及佇列已核准 |
| `packages` | 可放責任明確的跨 App 共用套件 | 必須建立 DTO 共用套件 |
| `docs` | 專案文件與後續模組／API 文件位置 | 本討論稿已成正式依據 |

依團隊 workflow 的方向，API Contract 應在需求與模組文件對齊後建立；OpenAPI 可由 Contract 衍生，不另維護一套互相衝突的手寫來源。

## 技術選項狀態

會議紀錄列有前端、後端與共用工具候選，例如 Redux、Zod、axios、Prisma、Redis、Docker、Jest 與 Supertest。這些是選項清單，不代表本專案全部會安裝或使用。每項技術應在對應需求與運作條件確認後，再記錄選用原因、責任範圍及替代方案。

## 部署方向與外部整合

- 9/29 會議以地端部署為方向；評估報告則比較雲端與地端，並另有雲端建議。初稿以較新的地端方向作為討論前提，但仍待專案確認。
- LINE 整合至少牽涉身分辨識、官方帳號入口與通知。需要確認實際採用的 LINE 服務、憑證管理及對外回呼方式。
- 若採地端部署，仍須規劃對外 HTTPS 網域、網路／防火牆設定、資料庫與附件備份、監控及故障復原。評估報告並未提供可直接執行的部署規格。
- 報告提出公司 Key 綁定風險；授權、解綁、稽核與敏感資料保護需在實作前具體化。
