# LINE 售服系統專案概覽（討論稿）

> 讓團隊先對齊要解決的問題、預期使用者與主要使用情境。本文件尚未核准，不作為正式開發範圍。

## 適用範圍

適用於 LINE 售服系統的專案啟動與範圍討論。具體模組規格、API 欄位與驗收標準待後續文件定義。

## 專案目標

評估報告提出：外部客戶透過 LINE 官方帳號進入售後服務入口，回報問題並查詢案件狀態；公司內部人員接收通知、受理、處理與追蹤案件。系統目標是讓問題回報和處理狀態可被記錄與追蹤，而非只存在於零散訊息中。

## 主要使用者

| 使用者 | 主要情境 |
|---|---|
| 外部客戶 | 綁定身分、建立問題回報、查詢案件狀態、接收通知 |
| 處理人員與備用處理人員 | 接收案件、受理、處理及更新結果 |
| 專案負責人 | 建立或管理售服專案、指派處理人員、追蹤進度 |
| 分析人員 | 檢視案件與統計資訊；可見範圍待確認 |

上述角色來自評估報告的使用對象與權限示意，尚未構成最終角色權限表。

## 主要使用情境

| 情境 | 評估報告中的構想 | 尚待釐清 |
|---|---|---|
| 身分綁定 | 由 LINE 入口登入，使用公司 Key 建立關聯 | Key 的核發、有效期、換發、防外洩與解綁方式 |
| 問題回報 | 選擇售服專案、問題分類及設備，填寫描述並上傳附件 | 必填欄位、附件限制與重複回報處理 |
| 案件處理 | 通知對應人員受理，更新狀態與處理結果 | 指派、轉派、結案及重開規則 |
| 案件追蹤 | 客戶查詢狀態，負責人檢視進度 | 各角色可查看的案件與歷程範圍 |

案件狀態可先以「待接單、處理中、已完成」作為討論起點；評估報告中的「逾期未接」究竟是狀態或提醒條件，仍待定義。報告也提出建立後 15 分鐘未接案的通知構想，但計時規則與通知對象尚未確認，不應視為已承諾的服務水準。

## 系統組成

- LINE 官方帳號：提供客戶入口與通知通道；登入、授權及訊息發送方式待設計。
- Web：提供客戶回報、案件查詢與內部管理介面。
- Server：提供 API、案件流程、權限判斷與 LINE 整合。
- 資料儲存與附件儲存：需要保存案件、關聯資料與附件，實際方案尚未決定。
- 部署環境：9/29 會議以地端部署為方向；對外 HTTPS、網路連線及維運方式仍待確認。
