# Developer 限制規則

Encoding: UTF-8

本文件只供需要修改專案的 Developer 任務使用；依 `entry.md` 在分流時載入，唯讀分析不載入。

使用者本次任務與已核准正式依據仍須先確定修改範圍；本文件不授權自行擴大範圍。

## 資料流與契約

- 未經任務要求或工程師確認，不得改變既有資料來源。
- 未經任務要求或工程師確認，不得改變既有更新順序或狀態管理方式。
- 未經任務要求或工程師確認，不得改變對外 Contract 或 public API。
- 不得繞過既有狀態或資料管理流程。
- 不得引入難以追蹤的隱式共享狀態。

## 架構

- 不得建立重複商業邏輯。
- 不得引入違反專案分層規則的依賴，或繞過規定的層級邊界。
- 不得未經授權進行大型重構或替換既有設計。

## 修改範圍

- 不得修改與本次任務無關的模組，也不得順手修正無關問題。
- 完成任務必須修改關聯檔案時，只能修改最小必要範圍，並在結果中說明原因。
- 關聯檔案仍受 `entry.md` 的模組與階段邊界限制，不得以「最小必要」為由提前修改其他模組。
- 共用檔案只有明列於已確認的當前階段範圍時才可修改；使用端所在的其他模組仍受各自階段限制。
- 跨模組修改未取得當前階段結果的明確確認前，不得開始下一階段。
- 不得在同一任務跨模組新增開發，或將新增開發改稱既有內容修改以繞過限制。
- 刪除既有功能、擴大任務範圍或執行不可逆操作前，須依 `entry.md` 取得工程師指示。

## 命名與結構

- 不得僅因個人偏好調整既有程式命名。
- 不得主動重新命名既有檔案或移動目錄。
- 只有本次任務明確要求，或完成任務確實必要且已向工程師說明影響並取得同意，才可重新命名既有檔案或移動目錄。

驗證失敗的處理與完成宣稱限制，統一依修改後載入的 `validation.md`，不在此重複定義。
