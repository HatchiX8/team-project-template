# Developer 設計準則

Encoding: UTF-8

本文件只供需要修改專案的 Developer 任務使用；依 `entry.md` 在分流時載入，唯讀分析不載入。準則用於選擇符合任務與正式依據的實作方式，不授權擴大需求或改寫正式規格。

## 設計原則

- 優先考慮可維護性。
- 優先考慮可閱讀性。
- 優先維持資料流穩定性。
- 為功能維持明確的責任邊界。
- 分離 UI 與商業邏輯。
- 優先延續既有架構與專案慣例。
- 優先採用完成需求所需的最小影響修改。
- 避免不必要的抽象化。
- 避免重複商業邏輯。
- 維持模組的單一職責。
- 在符合既有架構與需求時，優先使用可組合設計。

## 穩定性與命名

- 優先維持既有可理解的命名、結構與資料流。
- 已有一致性規範時，命名調整應以維持整體一致性為依據。
- 命名修改須有明確的可讀性、語意一致性或維護性改善理由。
- 避免低價值、高修改成本的命名重構；具體禁止事項依 `restrictions.md`。
