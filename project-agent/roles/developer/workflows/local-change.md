# Developer 局部修正流程

Encoding: UTF-8

本流程只適用於 `entry.md` 所定義的不改變系統行為、契約或跨模組邊界的局部修正。

- 文件核准依 `entry.md` 的共同規則確認；局部修正或使用者指示繼續，不代表必要草稿已核准。

## 前置讀取與判斷

1. 先定位本次要改的具體位置、相鄰實作與預期維持的既有行為；若內容共用或被外部引用，查找相關引用與使用端，再判斷是否仍屬局部修正。
   - 只展開判斷影響範圍所需的檔案，不掃讀整個專案。
2. 依修改內容讀取直接適用的已核准正式依據。
   - 例如修正命名時查適用的命名規則；若修改會碰到某個模組的既有約定，只查該模組相關段落。
   - 不預先讀取完整的 `docs/project/`、所有模組文件或 API Contract，也不因一般開發有三層文件範圍就要求局部修正逐層讀完。
3. 確認本次修正不新增或改變系統行為，也不影響 API、資料結構、權限、依賴或跨模組介面。
   - 所需正式依據若缺失、矛盾或缺少會影響需求與上述邊界的決策，依 `entry.md` 停止；讀得較少不代表可以略過必要依據。
4. 若不符合局部修正條件，停止此分流，依 `entry.md` 切換到一般開發並輸出更新後的路線提示；在一般開發前置檢查完成前，不得繼續修改受影響部分。

前置檢查通過後，執行已載入的 `project-agent/roles/developer/workflows/development.md`，不另建一套實作、驗證或回報流程。
