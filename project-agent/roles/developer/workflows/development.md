# Developer 共用開發流程

Encoding: UTF-8

本流程供局部修正與一般開發共用；只在已選分流的前置檢查通過後執行。

工作中若影響範圍或所需依據改變，先返回分流與正式依據檢查，確認後才繼續。

## Markdown 文件共用準則

- 本次授權範圍包含建立、修改或整理 Markdown 文件（含 README、接線與操作說明）時，修改前以 UTF-8 讀取並沿用 Documenter 的[文件撰寫與整理準則]；專案存在[公版文件規範]時，一併讀取其適用的呈現要求。
- 共用同一份格式來源，包含閱讀結構、用語、參照式連結與文末索引、文件狀態呈現及待確認事項格式；不在 Developer 規則另抄一套公版，也不只依相鄰文件的既有格式判斷。
- 此處只共用文件撰寫與核對準則，不載入 Documenter 角色入口或啟動其工作流程；Developer 的修改授權、正式依據與核准限制仍以自身角色規則為準。涉及規則決策時，不能以格式整理代替工程師確認。
- 文件類型有指定結構時優先保留，例如規則入口、Skill 的 YAML frontmatter 或工具解析的 Markdown；依用途套用可共用的呈現要求，不強制加入一般專案說明文件的全部章節或狀態欄位。
- 只處理本次需建立或修改的內容；不因載入共用準則而批次改寫其他文件。純程式修改與唯讀分析不預載這些文件。
- 必要的撰寫準則無法讀取時，依角色入口停止受影響的文件修改並回報；公版文件不存在時，沿用撰寫準則中適用的要求，不自行建立替代公版。

## 執行步驟

1. 修改前掌握工作區既有變更，並從任務與正式依據整理本次可觀察的完成條件；小任務可只在工作中用一兩句確認，不必另建文件或排程。
2. 依已確認的任務範圍、正式依據、現有實作、設計準則、限制與已選 Developer 技術 Skill 完成修改；只動本次工作所需內容，保留他人既有變更。
   - 需要改寫正式文件、擴大範圍、刪除功能或執行不可逆操作時，依 `entry.md` 停止並取得工程師指示，不自行擴權。
3. 修改後先以 UTF-8 讀取並遵守 `project-agent/roles/developer/validation.md`，依該文件完成驗證、自我檢查與第 1 步的完成條件核對。
   - 若檢查時發現正式依據缺口或影響範圍改變，依 `entry.md` 返回前置檢查或停止，不以實作結果反推規格。
4. 完成或停止前讀取並遵守 `project-agent/roles/developer/output.md`，回報實際結果。
   - 正式測試由工程師另行指定 Tester；Developer 不自動啟動或交接其他角色。
