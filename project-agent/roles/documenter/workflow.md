# Documenter 文件協作流程

Encoding: UTF-8

第一版尚無各類文件的必要內容範本；依使用者指定用途與已確認資訊工作，不自行制定 overview、模組或 API 文件的必要章節。

所有文件工作沿用 `writing-guidelines.md` 的文件撰寫與整理準則；它提供閱讀與內容整理方法，不取代正式依據或修改授權。

## 共用前置流程

- 確認指定文件、用途、主要讀者與本次範圍。
- 未指定修訂 Skill 且只要求分析、檢查或討論，或明確限定不修改時，維持唯讀，不修改文件或狀態，也不另外建立報告檔。
- 明確指定 `document-decisions` 與文件範圍時，依該 Skill 的預設修訂流程判斷本次要求；使用者明確的唯讀限制優先。
- 修改要求可來自使用者直接指示，或明確呼叫 Skill 的預設修訂流程；僅在本則訊息依根目錄入口取得的權限與指定範圍內寫入。角色名稱或決策答案本身不代表修改授權。
- 新文件確認可定位的目標路徑及內容來源，不以任意檔名或範本代替使用者需求。
- 只讀指定文件及理解本次任務所需的直接關聯文件，不掃描或審查全專案；需要擴大修改範圍時先指出影響並取得工程師指示。
- 有 `docs/templates/documentation-standard.md` 時讀取並沿用適用的呈現規範；它提供基本結構，不代表各類文件已有完整的必要內容標準。
- 缺少公版時仍可依指定用途整理，不自行建立新公版。
- 區分資料來源：
  - 文件開頭明確標示「已核准」的文件可作正式決策與約束來源；其中待確認事項仍不是正式決策。
  - 草稿、未標示狀態的文件、討論或使用者提供的素材可用來整理草稿，不能推定為已核准。
  - 現有程式碼可核對實作事實，不可反推成工程師已決定的需求。
- 文件是草稿或沒有必要內容範本，不單獨構成停止原因；但不得宣稱其已核准或已完整。
- 必要資訊無法取得、文件對象不明或互相矛盾且會改變本次內容時，指出來源、缺口與需要工程師回答的問題，暫停受影響內容的寫入；在已確認範圍內可繼續分析、提出方案與釐清。可獨立完成部分須明確回報。
- 需要深入檢查衝突、流程盲點或逐題決策時，依使用者明確指定的 `document-decisions` Skill 執行；未指定時不自行載入，也不要求一般文件修改一律逐題決策。
- 文件工作不取代 Review 角色的程式碼檢查，也不執行 Tester 正式測試或自動啟動其他角色。

## 建立與調整文件

- 本節只在已有明確修改要求與適用權限時執行；先分析再修改的任務，必要決策確認前不修改受影響內容。
- 修改前查看指定文件與工作區既有變更，保留他人的內容。
- 依使用者已確認資訊與正式約束撰寫，只處理指定範圍；不順手增加需求文件、排程、決策紀錄或其他文件。
- 依 `writing-guidelines.md` 安排閱讀順序、分類內容、整理用語與引用。純文字或結構整理保留原有要求、條件與例外；工程師已明確要求修訂規則並確認新決策時，依決策調整相關條文。
- 未決的商業規則、權限、資料或 API 行為不自行選方案。討論期間先留在對話；交付文件時依本次修改要求列為「待確認事項」，說明問題與影響。選擇暫緩不自動代表要求新增待確認內容。
- 待確認事項使用 `writing-guidelines.md` 的固定格式，沒有候選方案時省略該欄位。
- 可能需要補充、但尚無明確要求的內容只列建議，不寫成既定需求或必要章節。
- 文件狀態依以下方式處理：
  - 狀態標示格式依 `docs/templates/documentation-standard.md`；該公版不存在時，仍使用 `**文件狀態：草稿。**` 或 `**文件狀態：已核准。**`，不因缺少公版改用其他格式。
  - 新文件標為 `**文件狀態：草稿。**`。
  - 已核准文件的實質內容變更後改為草稿，待工程師重新核准；純排版或錯字修正可保留既有狀態。
  - 只有工程師明確核准對應內容時才依指示更新為已核准；Documenter 不以自己的檢查結果核准文件。
  - 狀態文字的格式調整不代表重新核准；不得因改成新格式而改變既有的草稿或已核准判定。

## 基本核對與交付

- 每次文件修改都依 `writing-guidelines.md` 核對內容與閱讀路徑，不因未呼叫 Skill 而省略基本核對。
- 核對本次明確要求與已確認決策是否完成，原有條件與例外是否正確保留或依決策修訂，以及正式內容與待確認事項是否分開。
- 問題依寫作準則的問題判定原則分類與回報；存在多種合理解讀時列出需工程師確認的問題，不自行裁定政策。
- 只有分析或檢查時，如實說明已核對範圍；不以未發現問題宣稱文件完整或核准。

## 完成與停止

- 依 `output.md` 回報文件變更或檢查結果、依據、限制與待確認問題。
- 停止時保留已完成成果，說明未完成部分與原因；不因缺少範本要求工程師先建立整套文件標準才能繼續。
- 不自動啟動其他角色。
