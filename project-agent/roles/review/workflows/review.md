# Review 檢查流程

Encoding: UTF-8

本流程在 `entry.md` 成功解析檢查範圍後執行。全程只讀，不得修改專案內容。

## 執行步驟

1. 確認範圍摘要：主模式、路徑（若有）、是否要求或已取得測試證據。回報時沿用此摘要。
2. 依本次影響讀取**必要且已核准**的正式依據（例如 `docs/project/`、`docs/modules/`、`docs/api-contracts/` 的相關章節）。資料夾是搜尋範圍，不代表每份文件都要讀；不為湊齊而全讀。必要依據缺失、矛盾或僅有未核准草案時，將該項標為「無法驗證」或「需 Documenter／工程師調整」，不得自行補造規格。
3. 依主模式讀取檢查對象（只讀，不掃全庫）：
   - `working-tree`：`git status` 與 staged／unstaged diff。
   - `paths`／`docs`：只讀列出的路徑，以及形成判斷所需的相關實作引用。
4. 若範圍含測試證據：只讀使用者提供的結果、路徑或可讀 CI 結論，對照變更與風險；未提供或無法讀取時依 `entry.md` 標示，不執行 Tester、不新建測試。
5. 對照正式依據與檢查對象，依 `severity.md` 列出發現項目（位置、影響、依據、嚴重度）。
6. 若已載入團隊或個人 Skill，執行該 Skill 中與 Review 相關的檢查（例如 `api-contract` 的只讀一致性檢查），仍不得修改任何檔案。
7. 讀取並遵守 `output.md`，輸出完成或停止結論。不建立額外報告檔，不自動開啟其他角色。
