# Review module 輸出契約

Encoding: UTF-8

## 共通原則

- 只在對話中輸出結果，不建立 Review 報告檔；明確說明本次未修改專案檔案。
- 依 `review.md` 的判定分別輸出 `審查狀態：完成／未完成` 與 `結論：PASS／FAIL／未判定`；不得在輸出階段重新猜測問題等級。
- 審查未完成但已有已證實的阻斷或嚴重問題時，結論仍為 `FAIL`；未完成且沒有此類問題時，結論為「未判定」，不得宣稱 `PASS`。
- `PASS` 只代表本次已檢查範圍未發現阻斷或嚴重問題、且沒有關鍵缺口；不代表未檢查範圍、建置或正式測試通過。
- 嚴重度使用 `阻斷`、`嚴重`、`中等`、`輕微`。
- 只有已證實的阻斷或嚴重問題列入「必須修正」，並作為 `FAIL` 的依據；中等與輕微問題列在「注意事項」或「改善建議」，不單獨改變 PASS／FAIL。
- 問題內文只引用連續的 `[證據 1]`、`[證據 2]` 等標記。
- 完整證據清單固定放在最後的 `## 證據`，同一證據只列一次。
- 每個「必須修正」問題至少引用一項文末實際列出的證據；不得引用不存在的標記，也不得用推測湊證據。
- 未確認事項、未取得的測試／CI 結果及檢查限制，標示為「未驗證」，放在「注意事項」或「驗證狀態」，不列為已證實問題。
- 本專案沒有舊版的 Review Profile 分流；摘要使用 `模式：模組檢查（module）`。
- 本角色不建立報告檔，因此不輸出「報告檔案」區塊。

## 回覆的區塊順序

1. `## 審查摘要`
2. `## 必須修正`（有內容才顯示）
3. `## 注意事項`（有內容才顯示）
4. `## 改善建議`（有內容才顯示）
5. `## 驗證狀態`
6. `## 檢查範圍`
7. `## 證據`（有已確認證據時顯示，永遠最後；完成回覆不得為空）

## 審查摘要與判定

- 摘要至少列出模式、模組對象、審查狀態、`PASS`／`FAIL`／「未判定」結論及「必須修正」數量；有注意事項時也列出數量。
- `PASS` 時寫 `必須修正：無`，不輸出空的「必須修正」區塊。
- `FAIL` 只在至少一項已證實的阻斷或嚴重問題存在時使用，即使審查未完成亦然；沒有此類問題但存在關鍵缺口時，回報「未完成／未判定」。
- 即使是 `PASS`，仍須在「驗證狀態」與「檢查範圍」清楚列出未執行或未涵蓋事項。

```text
## 審查摘要
- 模式：模組檢查（module）
- 對象：<模組名稱>
- 審查狀態：完成
- 結論：PASS
- 必須修正：無
```

## 發現項目

- 「必須修正」只收已證實的阻斷或嚴重問題，依影響程度排列。
- 每項須包含嚴重度、標題、位置、問題、影響、最小必要修正方向及引用的證據標記。
- 「注意事項」收已確認但不構成必須修正的風險、未確認事項與驗證限制；說明原因及可能影響。
- 「改善建議」只收非必要的後續改善，不混入必須修正問題。
- 沒有內容時省略整個「必須修正」、「注意事項」或「改善建議」區塊。

```text
## 必須修正
### [嚴重] <問題標題>
- 位置：path/to/file:line 或 symbol
- 問題：<已確認的問題>。[證據 1]
- 影響：<對流程、資料或 Contract 的影響>。[證據 2]
- 必要修正：<最小必要修正方向>。
- 證據：[證據 1]、[證據 2]
```

## 驗證狀態、檢查範圍與證據

- 「驗證狀態」分列 `已執行`、`未執行` 及原因；只把本次實際完成的唯讀檢查列為已執行，不把未執行的建置、測試或 Tester 工作寫成已通過。
- 「檢查範圍」分列 `已檢查` 與 `未涵蓋`；包含正式文件、程式碼範圍、逐項需求的核對結果摘要及實際參考的 Developer 技術 Skill。
- 必要需求須可追溯到文件位置、實作或缺失位置及核對結果；未驗證條目與原因須明列。
- 沒有適用技術參考時說明原因，不寫成已啟動 Developer Skill 流程。
- 「檢查範圍」記錄目前工作區的 `HEAD`、相關路徑的已暫存／未暫存／未追蹤狀態；檢查途中若重新核對變動，說明最後採用的目前工作區內容。
- 「證據」永遠是完成回覆的最後一個區塊；即使 `PASS` 且無問題，仍至少列出一項支持實際檢查範圍或判定的已確認證據。
- 每項證據只列一次，使用 `- [證據 N] 路徑、符號或既有結果：已確認事實` 格式；不貼無關或冗長程式碼。

## 中途停止

- 模組無法定位、必要正式依據缺失或矛盾、規則／技術參考檔無法讀取、規則牴觸、程式碼基準無法保持一致，或 `review.md` 判定有關鍵缺口時，停止未完成的 Review 工作。
- 沿用上述區塊順序；摘要寫 `審查狀態：未完成`，並指出停止階段、具體原因、路徑與下一步。
- 若已有已證實的阻斷或嚴重問題，寫 `結論：FAIL`，保留「必須修正」及其證據；否則寫 `結論：未判定`。
- 已取得的證據仍以連續標記列於最後；若完全沒有可核對證據，省略「證據」區塊並明說尚未取得，不得虛構項目。
- 列明已確認、未檢查與未驗證的範圍；不把部分檢查結果稱為完成，也不以籠統的「無法執行」取代原因。
