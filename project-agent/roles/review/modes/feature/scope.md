# Review feature 檢查範圍

Encoding: UTF-8

本文件只建立指定功能的需求與程式碼對照範圍，不在此階段判定實作是否正確。

## 定位正式依據

- 依使用者指定的功能名稱及所屬模組定位單一功能；名稱對應多個功能、模組不明或功能邊界不足以辨識時停止並請使用者確認，不自行改為 module 模式。
- 按需讀取 `docs/project/` 中直接適用的專案規範，以及 `docs/modules/` 中該功能的需求段落；涉及 API 時，再讀 `docs/api-contracts/` 的對應 Contract。這些目錄是搜尋層級，不要求全讀或固定檔名。
- 涉及 Web 或 Server 的架構、狀態管理、資料存取或其他 App 專屬技術約定時，按需查找 `apps/web/docs/` 或 `apps/server/docs/` 的相關文件。必要文件同樣須檢查開頭狀態；草案或未標示核准的內容不能當作正式依據。
- 對每份必要文件檢查開頭的 `狀態` 欄位；只有明確標為 `已核准` 才可作為正式依據。`草稿`、未標示或標示不明的文件不得取代正式需求；若沒有可替代的已核准依據，指出文件路徑與狀態後停止。文件中的待確認事項仍非正式需求。
- README、範本、討論、評估報告及程式碼現狀不能補造正式需求；正式文件互相矛盾或不足以判斷預期行為時，指出具體缺口後停止。
- 只整理指定功能的輸入輸出、正常與錯誤流程、資料與權限、直接使用端、對外介面及相關架構邊界。為每項必要需求記錄正式文件位置與預期行為，交由 `review.md` 逐項核對；不因要求散落在模組文件各章節而漏掉。

## 檢查基準

- 只以目前工作區的程式碼與正式文件為基準；開始 Review 時記錄其狀態，包含功能及直接關聯範圍內已提交、已暫存、未暫存及未追蹤的檔案。本階段不審查歷史版本。
- 記錄當時的 `HEAD` 與相關路徑的 Git 狀態；不把無關的工作區變更納入本次 Review。
- 使用者要求以歷史 commit、舊版文件或其他非目前工作區版本為基準時，說明本階段僅支援目前工作區並停止；不得自行改用當前內容給出歷史版本結論。使用者指定的檢查範圍仍須受 `feature` 模式的單功能邊界限制。
- 檢查途中相關檔案變動時，重新讀取並核對受影響的發現、需求條目與證據；無法取得一致基準時回報未完成。

## 定位實作與直接影響

- 依正式需求與 repository 結構定位該功能在 Web、Server 或共用套件的入口、實作、呼叫端與直接使用端；功能橫跨 App 時涵蓋完整直接資料流。
- 共用程式碼、型別或 API 可能影響其他功能時，查找直接引用以確認本功能的影響與回歸風險；只核對與本功能直接相關的使用方式，不藉此對其他功能或整個模組下結論。
- 記錄正式文件、程式碼、直接關聯範圍、實際技術及可取得的既有測試／CI 證據。要求的實作位置缺失時列為待核對事項，不自行建立檔案。
- 若指定功能無法從正式文件或實作中與其他功能區分，指出原因並停止；不得以任意選取的檔案集合代替功能邊界。
- 將範圍摘要與無法定位的部分交給 `skill-selection.md` 和 `review.md`。

## 停止與區分

- 必要正式依據缺失、互相矛盾或不足以判斷預期行為時，停止正式 Review；規格清楚但程式碼未遵守時，交由 `review.md` 核對並列為發現。
- 已核准技術選型與實際設定不符，且使範圍、準則或判準無法確定時，指出兩側依據後停止，不靜默擇一。
- 新發現若屬另一項獨立功能或整個模組的普遍問題，只記錄與指定功能可證實的影響；需要全面判定時請使用者另開相應 Review，不自行擴大模式。
