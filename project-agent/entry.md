# 專案模式入口

Encoding: UTF-8

本入口在使用者明確指定單一專案角色，或符合根目錄 `AGENTS.md` 的 Developer 任務延續條件時載入，負責驗證角色並分派至對應角色入口。除受限的 Developer 延續外，不根據任務內容或先前訊息自動選擇角色。

## 支援角色

- `developer`
- `documenter`
- `tester`
- `review`

## 載入流程

1. 從使用者本次訊息確認恰好指定一個支援的專案角色；未指定角色時，依 `AGENTS.md` 確認是否符合 Developer 任務延續。指定多個或無效角色時，依失敗處理停止，不以延續規則覆蓋本次明確指定。
2. 角色為 `developer` 時，以 UTF-8 讀取並遵守 `project-agent/roles/developer/entry.md`。
3. 角色為 `documenter` 時，以 UTF-8 讀取並遵守 `project-agent/roles/documenter/entry.md`。
4. 角色為 `tester` 時，以 UTF-8 讀取並遵守 `project-agent/roles/tester/entry.md`。
5. 角色為 `review` 時，以 UTF-8 讀取並遵守 `project-agent/roles/review/entry.md`。
6. 若有 `團隊 Skills：`，依列出順序從 `project-agent/skills/<skill-id>/SKILL.md` 載入每個 Skill。
7. 若有 `個人 Skills：`，以 UTF-8 讀取 `personal-assistant/skill-entry.md`，再依該入口載入指定 Skill。
8. 確認所有角色與 Skill 規則成功讀取，且彼此沒有不允許的組合或無法同時遵守的必要要求；後續角色流程另載入技術 Skill 時，仍須在執行受其影響的工作前重新檢查。
9. 首次進入或本次明確重新指定角色時，輸出角色入口的「進入提示」；Developer 延續時，輸出 Developer 入口的「延續提示」。輸出後才可以開始分析、修改、檢查或執行其他任務工作。

角色分派完成後，任務範圍、角色權限、應讀取的專案依據及後續工作步驟，由對應角色規則判斷；本入口不預先執行角色工作。

## 組合原則

- 角色負責主要工作流程、修改權限、專案邊界、驗證與回報。
- 團隊 Skill 提供團隊共同採用的特定工作方法。
- 個人 Skill 提供個別工程師的額外能力。
- Skill 不得擴大角色權限、降低專案限制或改變 Review 的唯讀邊界。
- 同一則訊息內，角色與 Skill 只載入規則一次，任務只分析、修改、驗證與回報一次；下一則 Developer 延續訊息仍須重新讀取必要規則。
- 團隊規則與個人 Skill 衝突時，以專案角色與團隊規則為準。
- Skill 的通用或可選建議與角色 Workflow、權限、專案限制或已核准正式依據不一致時，遵守後者並略過該建議；不得因此放寬限制或改寫正式依據。
- 若已載入 Skill 的必要步驟與角色 Workflow、權限、專案限制、已核准正式依據或另一個必須使用的 Skill 無法同時遵守，屬不可消解的牴觸，依失敗處理停止；不得只按載入順序擇一，也不得將必要步驟當作可選建議略過。

## 進入提示

全部必要入口成功讀取後，首次進入或本次明確指定角色時輸出對應角色入口定義的角色提示；Developer 延續時輸出該角色入口定義的延續提示。延續不免除重新讀取入口、確認任務範圍與檢查必要規則。

有指定 Skill 時，再依實際載入結果輸出：

```text
已載入團隊 Skills：<依序列出的 Skill ID>。
已載入個人 Skills：<依序列出的 Skill ID>。
```

沒有指定某一類 Skill 時，不輸出該行。不得在任何指定 Skill 載入失敗時輸出成功提示。

## 失敗處理

- 每次停止時，必須說明停止在哪個階段、已確認的具體原因，以及使用者可採取的下一步；不知道原因時應明確說明已知的錯誤，不得猜測。不得只說「無法執行」或「載入失敗」。
- 使用者指定其他角色時，指出實際指定值、支援的角色名稱，並請使用者改用其中一個角色。
- 同一則訊息指定多個專案角色時，列出衝突的角色並請使用者選定一個；不得自行挑選或依序執行。
- Developer 延續條件未成立時，指出原任務或範圍何處無法確認；若本次要修改範圍外內容，指出原範圍與新增影響，請使用者重新指定 `角色：developer` 並確認新範圍，不在原授權下修改範圍外內容。
- 專案入口或角色入口不存在、無法存取、內容不完整或無法以 UTF-8 正確讀取時，指出實際檔案路徑與已知的失敗原因，並說明需要修復該入口後才能繼續。
- 指定的 Skill 不存在、ID 無效、無法讀取或不允許與目前角色組合時，指出 Skill 來源、ID、已知的失敗原因，以及應修正指定值、檔案或組合中的哪一項。
- 發現不可消解的規則牴觸時，在修改或執行受影響工作前停止；指出兩側規則的實際路徑與牴觸要求、受影響的工作，以及已完成的動作。請使用者安排具權限者調整規則或正式依據後，再指示繼續；不得自行修改規則來解除牴觸或宣稱任務完成。
- 進入前失敗時不得輸出成功進入專案模式的提示；進入後才發現牴觸時，須明確回報已停止，不得以先前的進入提示表示可繼續。
- 失敗時不得改用個人助理或一般 Agent 模式繼續執行專案工作。
- 不得因目前位於 Repository 內就推測已進入專案模式。
